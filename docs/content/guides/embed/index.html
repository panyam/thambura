--- title: "Embed Thambura in your page" description: "Put the tala keeper and the thambura on a page of your own, with a spec, a slot for each island and one script." ---

The tala keeper and the thambura can go on any page, not only ours. Your page says which islands it wants and where, and one script from thambura.com does the rest. The islands keep their own styles, load their sounds from our site, and leave the rest of your page alone.

This page is a host itself: the examples below are live, loaded the same way your page would load them. Press Start on any of them.

The quickest embed

Three things go on your page: a spec saying which islands you want, an element for each one to go in, and embed.js.

<script type="application/json" data-thambura-spec>
{"islands": [{"name": "tala", "slot": "docs-tala"}]}
</script>
<div data-thambura-slot="docs-tala"></div>
<script type="module" src="https://thambura.com/static/embed.js"></script>

Which gives you this:

embed.js finds every data-thambura-spec script on the page once it has loaded, and mounts each one's islands in the elements whose data-thambura-slot matches. A page can have more than one spec, and each is a separate embed with its own sound and its own clock.

The spec

A spec is JSON, the same format our own pages are built from (see Getting started), except that you needn't name a layout.

{
  "islands": [
    {"name": "tala", "slot": "practice"},
    {"name": "thambura", "slot": "drone"}
  ],
  "instruments": []
}

Islands

Each island has a name, the slot it goes in, and an optional config.

NameWhat it isConfig
talaThe tala keeper: the talas, speed, beat images, the claps' sound and volume, and the speed and shruthi strip.instrumentControls: false leaves out the claps' controls, for a page that shows them elsewhere.
thamburaThe thambura's controls, docked in the slot: the Sound menu, the four views, Start and Copy link.None.
sessionThe speed and shruthi strip on its own, for a page with a thambura and no tala, which carries its own.None.

An island this version doesn't have, or a slot that isn't on the page, is logged to the console and skipped, and the rest of the spec still mounts.

Instruments

Islands are what you see. Instruments are what plays, and embed.js adds the ones your islands need: the thambura for a thambura island, and the claps for a tala (the tala itself makes no sound; it says when each beat falls, and the claps play it). You only name instruments to add something, such as a kit:

{"kind": "kit", "config": {"url": "/static/Resources/Kits/compmusic/kit.json"}}

A kit plays along with the tala and follows the thambura's Sa. No kit is published on thambura.com yet (#104), so there's no live example of one here.

Mounting from code

If your page builds its spec in code, import mount instead of writing a spec script:

const { mount } = await import("https://thambura.com/static/embed.js");

await mount(
  { islands: [{ name: "thambura", slot: "drone" }] },
  { root: document.querySelector("#my-drone"), theme: "dark" },
);
  • root is where to look for the slots. It defaults to the whole document; passing the element that holds them keeps two embeds' slots apart.
  • theme is "light", "dark" or "auto" (the default), which follows the visitor's system setting. A spec script takes it as data-theme.

{"islands": [
  {"name": "tala", "slot": "practice"},
  {"name": "thambura", "slot": "drone"}
]}

What it does on your page

  • Styles stay apart. Each island is in a shadow root with our stylesheet, so your CSS doesn't reach inside it and ours doesn't leak out. Size and place the slot elements as you like; the islands fill their width.
  • Everything loads from our site. Sounds, images, the thambura's rendering worker and the views that load on first use (the Lab, the Raagini) all come from next to embed.js. Our /static allows that from any origin.
  • Links open the app. Your address bar is yours, so an embed never writes to it. Copy link gives a link to the same setup on thambura.com.
  • No page-wide keys. The T key and Space belong to your page, so an embed doesn't take them.
  • Nothing installed. No service worker and no install button; those come with our pages only.

What to know today

Embedding is new, and a few things will change as other sites use it:

  • Settings are saved in your site's storage. An embed keeps the listener's choices (the shruthi, the thambura's sound, their presets) in your page's localStorage, under names starting with thambura.. Two embeds on one page share them, so the one changed last is what both open with next time (#144).
  • Each spec is separate. Every spec on a page, declared or passed to mount(), gets its own audio and clock, so two specs' Start buttons don't know about each other. Put islands that belong together in one spec.
  • The theme is chosen once. "auto" reads the visitor's setting when the embed mounts, and there's no call yet to switch it when your page's own dark mode changes.
  • There's no unmount yet. Once mounted, an embed stays until the page goes, so a single-page app that moves away from it should expect it to keep playing.

These are tracked on #86. If you're embedding Thambura and hit something else, open an issue.
